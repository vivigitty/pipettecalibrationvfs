# VFL Pipette Calibration and Certification

Generated Next.js 15 / React 19 / strict TypeScript web application and PostgreSQL database scripts, based on the five supplied requirement documents. Supabase-managed PostgreSQL is the recommended hosted database for the MVP; local Docker PostgreSQL remains available for integration testing. Original documents are unchanged.

## Deliverables

- `database/`: six standalone SQL scripts, in execution order, and database setup instructions.
- `prisma/`: all 15 business-table mappings, four equivalent SQL migrations, and repeatable ISO/admin seeding.
- `src/`: customer/configuration/instrument registers, batch asset registration, shared lab sittings, damages, calibration readings, pooled results, OIDC authorization, transactional audit and gated PDF/S3 services.
- `tests/`, `e2e/`: PostgreSQL constraint and read-only preview tests; unit tests are colocated with domain and input schemas.
- Docker Compose for optional local PostgreSQL/MinIO; Dockerfile for the application.

## Local Preview

Prerequisite: approved Node.js 22.18+ installation with npm on PATH. If your organization blocks executable installation, ask IT to provide Node; do not bypass device controls.

```powershell
Copy-Item .env.example .env
npm install
npm run db:generate
npm run dev
```

If `.env` already existed before the Supabase update, add `DIRECT_URL` from `.env.example`; for preview it can remain a placeholder because no database connection is made.

Open http://127.0.0.1:3000/assets after the server starts. `.env.example` explicitly selects `APP_MODE=preview`: sample records are read-only, the ISO resolver is live server code, and writes/certificate issuance are forbidden. Preview is prohibited in production. If port 3000 is occupied, update `AUTH_URL` and run `npm run dev -- --port 3001`.

The dependency lockfile has now been generated by npm. Review and commit it, then use `npm ci` for repeatable installations.

## Live Development

1. Create a Supabase project. In its **Connect** panel, copy a transaction-pooler connection for the app and a direct connection for Prisma migrations. Set these as `DATABASE_URL` and `DIRECT_URL` in `.env`. If the direct host is unreachable on your network, use Supabase's session pooler for `DIRECT_URL`; do not use its transaction pooler for migrations. If the pooler URL does not already include it, add `pgbouncer=true` to `DATABASE_URL` for Prisma. Keep both URLs private, URL-encode special characters in passwords, and never commit `.env`.
2. Set `APP_MODE=live`, `AUTH_SECRET`, `AUTH_URL`, and the Microsoft Entra client ID/secret/tenant issuer in `.env`. Register the callback URL `http://127.0.0.1:3000/api/auth/callback/microsoft-entra-id` in Entra.
3. Run `npm run db:generate` and `npm run db:deploy`. Prisma applies the reviewed migrations through `DIRECT_URL`; do not also run the standalone schema scripts against the same database. For least privilege, apply `database/005-app-grants.sql` as the Supabase database owner, create a separate login role in Supabase, and grant it membership in `vfl_app`. Verify role creation and grants in the Supabase project before relying on them; managed database permissions can differ.
4. Set `DATABASE_URL` to the connection URL for the new app login. Set `SEED_ADMIN_EMAIL`, `SEED_ADMIN_SUBJECT` (the actual OIDC `sub`), and `SEED_ADMIN_NAME`, then run `npm run db:seed`. No local passwords, auto-enrollment, or default administrator identity exists. Seeding an existing subject never escalates its role.
5. Configure `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` for an S3-compatible store, then create the `vfl-certificates` bucket. MinIO is available locally through Docker Compose; production should use a scoped service account, encryption, private buckets, versioning and immutability policies, not root storage credentials.
6. Add customers, range configurations with all limit pairs, and instruments; register jobs; create a lab sitting; start calibration from the asset detail; enter ten masses per lot; complete the session. Failed sessions allow another attempt. Passed-session corrections require an admin and no active certificate.

The latest `Database_Design.md` v1.2 and `Spec.md` control conflicts in older task text: **15 tables**, **pooled results per volume**, and **US Letter certificate size**. An asset is one pipette in one job. Unscaled NUMERIC preserves stored measurement precision; calculations use 50 significant decimal digits. Z is the only calculation explicitly rounded (four decimal places).

## Certificate Release Gate

PDF generation is implemented but disabled unless `CERTIFICATE_TEMPLATE_APPROVED=true`, `CERTIFICATE_LOGO_URL`, and `CERTIFICATE_FOOTER` are configured. The actual sample PDF, VFL logo and footer assets are absent from this workspace. The draft uses Helvetica and an approximate US Letter layout; it is **not** certified as an exact reproduction. Supply/register the approved Arial font and reproduce the actual sample before approval. Continuation pagination, thermometer due-date wording and signed inaccuracy need VFL acceptance. Do not enable the flag merely to bypass the gate.

Only completed passing sessions with all readings can issue PDFs. A UUID `Idempotency-Key` allows an identical request to return its stored record; another issuance attempt conflicts. Downloads serve stored bytes and verify SHA-256. Admin voiding exists as a reason-required API action. The stored object is immutable and remains in history. Object-store writes cannot participate in PostgreSQL transactions: failed transactions can leave an unreferenced object; add a reconciliation/retention job before production.
