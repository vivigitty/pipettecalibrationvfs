# VFL Pipette Calibration and Certification

Generated Next.js 15 / React 19 / strict TypeScript web application and PostgreSQL database scripts, based on the five supplied requirement documents. Supabase-managed PostgreSQL is the recommended hosted database for the MVP; local Docker PostgreSQL remains available for integration testing. Original documents are unchanged.

## Deliverables

- `database/`: seven standalone SQL scripts, in execution order, and database setup instructions.
- `prisma/`: all 15 business-table mappings, equivalent SQL migrations, and repeatable ISO/admin seeding.
- `src/`: customer/configuration/instrument registers, batch asset registration, shared lab sittings, damages, calibration readings, pooled results, Supabase email/password sign-in with app roles, transactional audit and gated PDF services.
- `tests/`, `e2e/`: PostgreSQL constraint and read-only preview tests; unit tests are colocated with domain and input schemas.
- Docker Compose for optional local PostgreSQL; Dockerfile for the application.

## Local Preview

Prerequisite: approved Node.js 22.18+ installation with npm on PATH. If your organization blocks executable installation, ask IT to provide Node; do not bypass device controls.

```powershell
Copy-Item .env.example .env
npm install
npm run db:generate
npm run dev
```

If `.env` already existed before the Supabase update, add `DIRECT_URL` from `.env.example`; for preview it can remain a placeholder because no database connection is made.

Open http://127.0.0.1:3000/assets after the server starts. `.env.example` explicitly selects `APP_MODE=preview`: sample records are read-only, the ISO resolver is live server code, and writes/certificate issuance are forbidden. Preview is prohibited in production. If port 3000 is occupied, update `AUTH_URL` and run `npm run dev -- --port 3001`.

The dependency lockfile has now been generated by npm. Review and commit it, then use `npm ci` for repeatable installations.

## Live Development

1. Create a Supabase project. In its **Connect** panel, copy a transaction-pooler connection for the app and a direct connection for Prisma migrations. Set these as `DATABASE_URL` and `DIRECT_URL` in `.env`. If the direct host is unreachable on your network, use Supabase's session pooler for `DIRECT_URL`; do not use its transaction pooler for migrations. If the pooler URL does not already include it, add `pgbouncer=true` to `DATABASE_URL` for Prisma. Keep both URLs private, URL-encode special characters in passwords, and never commit `.env`.
2. Set `APP_MODE=live`, `AUTH_SECRET` (at least 32 random characters), `AUTH_URL=http://127.0.0.1:3000`, `SUPABASE_URL`, and `SUPABASE_PUBLISHABLE_KEY` in `.env`. Get the project API URL and publishable key from Supabase project settings; the legacy anon key also works here. Never use a secret/service-role key. Microsoft Entra settings are no longer used. See the account setup in `database/README.md`.
3. Run `npm run db:generate` and `npm run db:deploy`. Prisma applies the reviewed migrations through `DIRECT_URL`; do not also run the standalone schema scripts against the same database. For least privilege, apply `database/005-app-grants.sql` as the Supabase database owner, create a separate login role in Supabase, and grant it membership in `vfl_app`. Verify role creation and grants in the Supabase project before relying on them; managed database permissions can differ.
4. Set `DATABASE_URL` to the connection URL for the new app login. Create a confirmed email/password account in Supabase Authentication, then set `SEED_ADMIN_EMAIL`, `SEED_ADMIN_SUBJECT` (that Supabase Auth user's UUID), and `SEED_ADMIN_NAME`. Run `npm run db:seed` before this account's first sign-in. No passwords are stored in the application users table, and no account receives app access automatically. Seeding an existing subject never escalates its role. Additional users register at `/signup`, confirm their email, and attempt sign-in to submit an inactive request. An app admin assigns their role and approves access in `/users`. Enable Supabase signups, email confirmation, and custom SMTP; see `database/README.md` for URL configuration and approval steps.
5. In Pipette inventory, register pipettes and select or add customers and range configurations inline. Open a pipette and use Start calibration to select existing lab conditions or add a new sitting inline, including all three instruments (balance, air thermometer and water thermometer). Administrators can add missing instruments within that form. Review the selected conditions, start calibration, enter ten masses per lot and complete the session. Failed sessions allow another attempt. The sidebar no longer lists separate setup sections; existing `/customers`, `/ranges`, `/instruments` and `/lab-dimensions` maintenance pages remain accessible directly, with their existing permissions.

Instrument calibration versions are unique by **serial number + instrument type + calibration due date**. UUID primary/foreign keys and historical snapshots are retained. The same instrument version can be reused for multiple pipettes and lab sittings on the same or different dates, provided its calibration is valid for each sitting's process date. Instrument pickers filter by type and validity before pagination.

Before deploying this workflow to an existing Prisma-managed database, run `npm run db:generate` and `npm run db:deploy` to apply `20261113000100_instrument_type_identity`. For a database managed with the standalone SQL scripts instead, apply only `database/007-instrument-type-identity.sql` as the database owner. The migration changes only the instrument uniqueness constraint; it does not replace IDs or modify existing readings.

The latest `Database_Design.md` v1.2 and `Spec.md` control conflicts in older task text: **15 tables**, **pooled results per volume**, and **US Letter certificate size**. An asset is one pipette in one job. Unscaled NUMERIC preserves stored measurement precision; calculations use 50 significant decimal digits. Z is the only calculation explicitly rounded (four decimal places).

### Login troubleshooting

If Vercel logs `JWTSessionError` with `Cannot read properties of undefined (reading 'id')` in the JWT callback, deploy the version that guards `user?.id` in `src/lib/auth.ts`. Auth.js supplies `user` during sign-in, but subsequent session reads must retain the existing token without accessing an absent user. After redeploying, sign in again if the failed session was cleared.

### Reading-save troubleshooting

The PDF renderer is loaded only for certificate downloads, so PDFKit initialization failures cannot prevent lot-reading endpoints from loading. Internal API failures log the underlying error and request ID on the server; the UI includes that ID without exposing internal error details. If saving still fails after deployment, match the displayed request ID to the server log rather than relying on an unrelated certificate error.

## Certificate Release Gate

PDF generation is implemented but disabled unless `CERTIFICATE_TEMPLATE_APPROVED=true` and `CERTIFICATE_FOOTER` are configured. Certificate rendering now prefers `public/VFL_Logo.png` for the top-right logo, with `CERTIFICATE_LOGO_URL` used only as fallback if the local file is unavailable. The draft uses Helvetica and an approximate US Letter layout; it is **not** certified as an exact reproduction. Supply/register the approved Arial font and reproduce the actual sample before approval. Continuation pagination, thermometer due-date wording and signed inaccuracy need VFL acceptance. Do not enable the flag merely to bypass the gate.

Only completed passing sessions with all readings can issue PDFs. Session-level download is generated on demand and uses the filename `InventoryNumber_ProcessDate.pdf`. Object storage for certificate retention is disabled in this build, so certificate downloads are intentionally ephemeral.

For Vercel and standalone deployments, `next.config.ts` explicitly includes PDFKit's dynamically loaded standard fonts and shared chunks in the `/api/v1/*` function traces. If certificate downloads report a missing `pdfkit/js/standard-fonts/Helvetica.cjs`, deploy a fresh build containing this tracing configuration; the files must be packaged at build time.
